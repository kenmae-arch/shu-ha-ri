# 事業計画

## 事業モデル

海外テック・ディープリサーチメディアを主軸に、読者基盤→マイクロSaaS→導線収益の順で直列に育てる。3本を並列で立ち上げない（ひとり社長＋AI体制では各柱が中途半端になるため）。

```
フェーズ1          フェーズ2               フェーズ3
リサーチメディア → 有料ニュースレター  →  マイクロSaaS（読者の課題から）
（読者をつくる）    （深い読者と収益）      （メディアが集客装置）
                          ＋アフィリエイト導線
```

## フェーズ1: メディアの立ち上げ（いま〜3ヶ月）

- **やること**: 週1本のディープリサーチ記事（Zennまたはnote）。X発信は記事の「使える断片」を配る導線として運用
- **記事の型**: 守破離リーディング3部構成（`company/vision.md`）。品質基準は `docs/content-guidelines.md`
- **収益**: なし（意図的に）。SEOと被リンクの資産化を優先
- **成功基準**: 記事12本、検索流入の発生、保存・引用・質問の獲得。特に「読者からの質問」が第2・第3フェーズの原料になる

## フェーズ2: 収益化の開始（3〜6ヶ月）

- **やること**: 有料ニュースレター（note メンバーシップ / Substack を比較して決定）。無料記事は継続し、深掘り・先行版を有料に
- **あわせて**: 記事内で実際に使ったツールのアフィリエイト導線を、体験ベースでのみ設置（使っていないものは紹介しない）
- **成功基準**: 有料読者の獲得と、読者からの課題・質問が継続的に届く状態

## フェーズ3: マイクロSaaS（6ヶ月〜）

- **やること**: 読者の課題リスト（`business/reader-insights.md` に蓄積予定）から、最も繰り返し現れるニッチ課題を1つ選び、小型Webツールを開発・月額課金化
- **原則**: 「大量構築」はしない。1個作る→メディアで集客→保守しながら検証→うまくいったら2個目
- **根拠**: 個人開発SaaSの最大の死因は集客。メディアで読者を先に持つことでこの弱点を消す

## 差別化

- 翻訳・速報メディアとの違い: 「破」（検証・反証・限界）と「離」（日本の実務者への応用）まで書く
- AI量産メディアとの違い: 全記事に人間承認ゲート。出典と確認日を明記し、確認できないことは書かない
- 個人ブログとの違い: AI社員による調査体制で、個人の可処分時間を超える調査量を毎週安定して出す

## リスクと対応

| リスク | 対応 |
|---|---|
| AI量産コンテンツとみなされ検索評価を失う | 全自動投稿をしない。一次情報リンク・独自検証・実名運用で品質を示す |
| 著作権・引用の問題 | 引用は必要最小限＋出典明記。翻訳転載はしない。原文は要約と自分の分析で扱う |
| 海外情報の誤読 | リサーチ社員の確度ラベル（確認済み/単一情報源/未確認）とレビュー社員のファクトチェックを必須化 |
| 続かない | 週1本に固定。週2本以上やりたくなっても品質に投資する |

## 数字の置き場

KPIの実測値は `business/kpi.md`。読者から拾った課題は `business/reader-insights.md`（フェーズ1中に開設）。
