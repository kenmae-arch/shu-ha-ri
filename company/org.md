# 組織図

## 設計思想

AI社員は「役職」ではなく「業務単位」で採用する。「AIマーケティング責任者」のような抽象度の高い社員は作らない。入力・出力・完了条件・禁止事項が明確に定義できる狭い業務だけをAIに任せ、うまくいったものだけを残して少しずつ広げる。

## 体制

```
社長（人間）
 │  最終承認・判断基準の言語化・週次レビュー
 │
 ├─ 企画      … テーマ案と企画書を作る          (.claude/agents/planner.md)
 ├─ リサーチ  … 調査とファクトチェック          (.claude/agents/researcher.md)
 ├─ ライター  … 構成・初稿・改稿                (.claude/agents/writer.md)
 ├─ レビュー  … 公開前の品質チェック（門番）    (.claude/agents/reviewer.md)
 ├─ SNS       … X向け投稿案の作成               (.claude/agents/sns-marketer.md)
 └─ 秘書      … バックログ・KPI・週次整理       (.claude/agents/secretary.md)
```

## 責任分界

| 判断 | 誰がする |
|---|---|
| 何を作るか（企画の採用） | 社長 |
| どう作るか（構成・表現） | AI社員が提案、社長が修正指示 |
| 公開してよいか | **社長のみ**（レビュー社員の合格は必要条件であって十分条件ではない） |
| ルール・計画の変更 | 社長 |
| バックログ・KPIの記録 | 秘書（事実の記録のみ。方針判断はしない） |

## 採用・解雇のルール

- 新しいAI社員を作るのは、**チャットで同じ依頼を3回以上繰り返し、うまくいく指示の型が固まったとき**だけ
- 2週連続で成果物が全部差し戻されたAI社員は、指示書（agentファイル）を見直す。直らなければ廃止する
- 社員定義の変更履歴はgitに残す。「なぜ変えたか」をコミットメッセージに書く
