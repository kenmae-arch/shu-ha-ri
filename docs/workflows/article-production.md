# 業務手順書: 記事制作

記事1本を企画から公開準備まで進める標準フロー。`/write-article` スキルがこの手順を実行する。

## フロー全体

```
企画 → [社長承認] → リサーチ → 構成 → [社長確認] → 初稿 → レビュー → 改稿 → [社長承認] → 公開準備完了
```

社長のゲートは3箇所。それ以外はAI社員が進める。

## 手順

### 1. 企画（担当: 企画）

- `business/backlog.md` の記事候補、過去記事、`company/vision.md` の読者像を読む
- テーマ案を3つ出し、それぞれ `templates/article-brief.md` の形式で企画書にする
- 出力先: `content/articles/NNN-スラッグ/brief.md`（採用されたもののみ残す）

**→ 社長ゲート①: どの企画で書くか決める。**

### 2. リサーチ（担当: リサーチ）

- 企画書の「要調査事項」を調べ、`research.md` に出典つきでまとめる
- 確認できなかったことは「確認できなかった」と明記する（推測で埋めない）

### 3. 構成（担当: ライター）

- 企画書とリサーチを読み、見出し構成と各見出しの役割・結論を `outline.md` に書く
- この時点では本文を書かない

**→ 社長ゲート②: 構成を確認し、修正指示または続行を指示する。**

### 4. 初稿（担当: ライター）

- `docs/style-guide.md` に従い `draft.md` に本文を書く。ステータスは `下書き`
- 書き終えたらセルフチェック（文体ルール・禁止表現）をして `レビュー待ち` にする

### 5. レビュー（担当: レビュー）

- チェックリスト（reviewerの指示書内）で検査し、指摘を `review.md` に書く
- 合格基準を満たすまでライターと往復する（最大2往復。収束しなければ社長へ）

### 6. 公開準備（担当: ライター）

- レビュー合格版を `article.md` として確定し、タイトル案3つ・想定公開先を添える

**→ 社長ゲート③: 最終確認し、`承認済み` に変更。実際に公開したら公開URLを記載して `公開済み` に変更する。**

### 7. 事後処理（担当: 秘書）

- `business/backlog.md` のタスクを完了に、`business/kpi.md` の公開本数を更新
- SNS担当に告知投稿の作成を依頼できる状態にする

## 品質の原則

- 1記事の分量目安: 2,000〜4,000字。長さより「読者の次の一歩が明確か」を優先
- この会社の実践を最低1つ、具体例として入れる（一次情報主義）
